# Known issues — XR32 DAY+NIGHT test build, trunk r12337 (testing-1)

Every item was measured; none is new in this build unless it says so.

## 1. A 32-bit image can be a few pixels smaller than the 16-bit one at some zoom levels

The 32-bit (XR32) scaler sizes an image to `floor(size × zoom)`. The 16-bit scaler first pads the image to a multiple
of the zoom's denominator, so it can come out larger. Measured on toolbar icons of 31, 33 and 40 px:

| Zoom | Difference |
| --- | --- |
| 3/4, 3/2 and 4/3 | the 32-bit image is 1–3 px smaller |
| 9/8, 5/4, 11/8 and 7/4 (the new steps of r12336, denominator 8) | up to 10 px, and there it is the 16-bit image that is larger than its toolbar cell |

The 32-bit image always fills its cell exactly. This is older behaviour, not a regression.

## 2. One catenary wire column differs from the 16-bit renderer away from 100 %

pak128.german's `catenary_120`, north-east wire image, has a wire column 1 pixel wide. Away from 100 % zoom the 32-bit
and the 16-bit scalers keep different rows of that column: at 9/8–11/8 the 32-bit image drops its upper 17–21 rows,
and when zooming out the 16-bit image drops more.

The public prototype already had this. It is not the extreme-zoom bug fixed in this build.

## 3. Shared images (image identity)

When paks load, the game merges images whose ordinary 16-bit data is byte-identical, **without looking at their 32-bit
data**. Two objects with identical 16-bit images but different 32-bit pictures can therefore end up showing the same
32-bit picture. Seen in testing:
- a test vehicle showed another vehicle's night picture;
- pak128.german's `catenary_tram_90` uses `catenary_160`'s 32-bit mast when both are built with XR32 (their 16-bit
  masts are identical).

Open; it must be solved before any proposal to Simutrans.

## 4. Coast water tiles have no 32-bit detail

The water tiles on sloped coasts are generated by the game itself from the 16-bit water images, so they stay 16-bit
even when the pakset's water is 32-bit. Open-sea tiles do use the 32-bit images.

## 5. 32-bit interface images get dark at night

Toolbar icons and other interface images that come with 32-bit data are darkened at night like the map. 16-bit
interface images keep their day colours, as before. Measured with Frank's pak64.german and theme-large at 2:49 am in
the game: with `SIMUTRANS_XR32=1` the toolbar's average brightness at night is about a third of its brightness by day;
without it, the toolbar does not change.

The r12322 test build does the same, so this is not new in this build.

## 6. At 3/2 the 32-bit picture can depend on the zoom step before it

With `SIMUTRANS_XR32=1`, the map at 3/2 differs by a few pixels (28 px measured) depending on whether the zoom step
before it was 2/1. Going back through 100 % restores it. The 16-bit renderer has no such effect. The r12322 test
build does the same, so this is not new in this build.

## 7. Night pictures cost memory

An object with a night picture keeps a second full-size 32-bit picture: about **75–93 %** more 32-bit image memory,
and zoom changes and night steps rebuild its images about **20–47 %** slower, in our test sets. Normal drawing was
not measurably slower.

## 8. The pak syntax is a prototype

`night_images=1`, `X.night.png` and the player-colour images are a syntax under review, not a final pak format:
- build test content only with the makeobj of this release;
- a night picture that is shifted against the day picture is only detected where the object becomes transparent at
  night;
- after a fatal makeobj error, a partial output file can remain (the exit code is non-zero).

## 9. Builds and platforms

- XR32 is built only with CMake for SDL2 and SDL3. The GDI backend and the plain Makefile build are 16-bit.
- This release is x86_64 only: Windows (SDL2, SDL3) and Linux (SDL2, glibc 2.38 or newer).
- Not tested: macOS, Android, ARM.

## Fixed in this build

**Thin 32-bit images at strong zoom-out** (reported by makie). An image that becomes less than one pixel wide or high
at a zoom level was drawn at its full 100 % size and at its 100 % offset. Catenary poles appeared big and beside the
track from zoom 3/8 down, and 1-pixel features from 3/4. Now such an image is left out, exactly as the 16-bit renderer
does.
